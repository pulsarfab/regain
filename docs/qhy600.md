# QHY600M cameras

Use the same Regain camera in NINA, native Windows ASCOM or the Alpaca server.
Choose **Direct USB** for the Rust driver or **Vendor SDK** for QHY's installed
library. SDK fallback is optional and remains active until disconnect.

## Windows setup

1. Install the QHY camera system driver and connect external power and USB.
   Both backends need the Windows firmware/system driver. Direct mode does not
   load `qhyccd.dll`.
2. For SDK mode or fallback, install the QHY AllInOne SDK. Regain looks for
   `C:\Program Files\QHYCCD\AllInOne\sdk\x64\qhyccd.dll`. Set `REGAIN_QHY_SDK`
   to an alternative trusted x64 library path before starting your frontend.
   The SDK and its sibling dependencies are not bundled with Regain.
3. Select **PulsarFab regain Retryable Camera** in NINA, a **Retryable Camera
   1–4** ASCOM entry, or a camera slot in the Alpaca setup page. Refresh cameras
   while disconnected, choose **QHY600M**, and select a backend.
4. Save the complete camera ID, such as `QHY600M-96763b4ab6a79e117`, to distinguish
   multiple cameras. Close other controllers before connecting.

NINA FITS files use `INSTRUME=QHY600M`. Its optional **Save camera serial number
in image metadata** setting writes the connected QHY ID as `CAMSER`.

## Current scope

| Feature | Direct USB | SDK backend |
|---|---|---|
| Photographic DSO 16BIT, read mode 0 | Yes | Yes |
| 9600 × 6422 RAW16, bin 1 | Yes | Yes |
| Region of interest | Software crop of full sensor | Software crop of full sensor |
| Gain, offset, QHY USB traffic | Yes | Yes |
| Temperature, power, target and cooler enable | Yes | Yes |
| [QHYCFW3 XL 9-position wheel](qhycfw3.md), camera 4-pin connection | Yes; shared camera handle | Yes; shared SDK handle |
| Circular diagnostics and live logging toggle | USB commands and timings | SDK calls and timings |
| Same-frame reread after a failed download | No | No |
| [Opt-in pipe-worker video](qhy600-video.md), mode 0 full-frame RAW16 | Yes | Not exposed |
| Frontend Live View, hardware binning, other read modes | Not exposed | Not exposed |
| Dew heater or privileged USB reset | Not exposed | Not exposed |

Full-resolution SDK video tests passed in RAW8 and RAW16 for read modes 0–3,
8 and 9, including stop/restart. Hardware 3×3-bin video did not return frames in
the test. These are reference results for future support; Regain's frontends
still expose the single-exposure mode listed above. See the
[video acceptance record](qhy600-development.md#sdk-video-acceptance-2026-11-03).

Direct mode is experimental and checks the traced U3G20 hardware signature and
2024-10-18 firmware before writing commands. Unrecognized revisions are rejected
and require SDK mode. Other QHY models are not currently selectable. The SDK's
one-hour exposure limit is exposed; physical acceptance used full-frame
five-second captures, not hour-long integrations.

The cooler uses Regain's bounded controller in both backends. Its live limit
defaults to 25 percentage points per five seconds. Unchanged outputs get a
five-second keepalive; explicit disconnect requests zero power. This camera's
reported output can ramp down for tens of seconds after disconnect. A failed worker
can restore its previous cooling demand before ramping additional recovery power.

QHY image reads consume data. Regain never pretends a failed read is a retained
frame: it discards the failed acquisition and follows the configured replacement
exposure policy. Ordinary successful frames keep the existing camera session;
cancelled direct acquisitions get explicit cleanup before another exposure.
Direct transfers currently use the traced 81,920-byte read size; the ZWO direct
read-size setting does not change QHY transfers.

## Diagnostics and verification

NINA records driver events under `%LOCALAPPDATA%\NINA\Logs`; search for
`PulsarFab regain` or `QHY600M`. Default circular transfer history is under
`%LOCALAPPDATA%\Regain\Diagnostics` and is included in diagnostic batches on
errors. Image payloads are not included in those logs.

See the [protocol and acceptance record](qhy600-development.md) for traced
registers, timing, SDK comparison, hardware tests and remaining scope.
